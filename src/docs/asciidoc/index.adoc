== Overview

Donggree 서비스 API 문서입니다.

== API

=== 인증

==== 토큰 갱신

리프레시 토큰(HttpOnly 쿠키)으로 새 액세스 토큰을 발급한다.

operation::auth-refresh[]

==== 로그아웃

리프레시 토큰 쿠키를 삭제하여 로그아웃 처리한다.

operation::auth-logout[]

==== 이용 제한(정지) 회원

신고 처리나 관리자 판단으로 정지된 회원은 정지 종료 시각까지 동그리를 이용할 수 없다. 로그인하면 토큰을 발급하지 않고 프론트 로그인 콜백으로 `suspendedUntil`·`suspensionDays`·`suspensionByReport` 쿼리를 넘긴다. 이미 로그인해 있던 회원의 API 요청과 토큰 재발급(`/auth/refresh`)은 403(AUTH403_2)을 반환하며 `result`에 `suspendedUntil`(다시 이용 가능 시각)·`days`(정지 일수)·`byReport`(신고 처리 정지 여부)를 담는다. 정지는 탈퇴 후 재가입(같은 회원 ID 재활성화)으로 풀리지 않는다.

operation::user-delete[]

=== 관리자 커리큘럼 관리

==== 과목 분류 조회

과목 분류를 동적 다중 필터로 조회한다. 각 필터(areaTypeIds·courseTypes·years)는 여러 값을 지정할 수 있고, 지정하지 않으면 전체 조회다. areaTypeIds·courseTypes는 하나라도 일치(IN), years는 지정 연도 중 하나라도 적용 입학년도 범위(start≤year≤end)에 포함되면 매칭(OR)한다. 응답에는 area_type_id 대신 영역 이름(areaName)과 과목 tag가 포함된다.

operation::admin-course-classification-search[]

==== 과목 분류 배치 업서트

등록·수정을 구분하지 않고 여러 과목 분류를 한 번에 변경한다. 각 항목의 id가 null이면 신규 등록, non-null이면 전체 교체(수정)다. 전체가 하나의 트랜잭션으로 처리되어 일부라도 실패하면 모두 롤백된다. 결과 ID 목록을 입력 순서대로 반환한다.

operation::admin-course-classification-upsert[]

==== 이수 영역 조회

이수 영역 전체를 조회한다. 과목 분류 필터의 선택지로 사용된다.

operation::admin-area-type-list[]

==== 규칙 종류 조회

규칙 종류(rule_type) 전체를 조회한다. 졸업 규칙 필터의 선택지로 사용된다. 읽기 전용.

operation::admin-rule-type-list[]

==== 졸업 규칙 조회

졸업 규칙을 동적 다중 필터로 조회한다. ruleTypeIds·courseTypes는 하나라도 일치(IN), 미지정=전체. courseType은 rule_type 소유 컬럼이며, 정렬은 course_type(NULLS LAST) 그다음 rule_type_id 순이다. 응답에 rule_type 정보와 ruleConfig(JSON 객체)가 포함된다.

operation::admin-graduation-rule-search[]

==== 졸업 규칙 배치 업서트

등록·수정을 구분하지 않고 여러 졸업 규칙을 한 번에 변경한다. 각 항목의 id가 null이면 신규 등록, non-null이면 전체 교체(수정)다. 전체가 하나의 트랜잭션으로 처리되어 일부라도 실패하면 모두 롤백된다.

operation::admin-graduation-rule-upsert[]

==== 졸업 요건 세트 목록 조회

졸업 요건 세트를 동적 필터로 조회한다(요약, 연결 규칙 미포함). departmentId는 특정 학과, collegeId는 해당 단과대 소속 학과 전체(둘 다 주면 교집합), year는 단일 연도로 적용범위(start≤year≤end)에 포함되는 세트만. 미지정=전체. 연결 규칙 ID는 단건 상세 조회에서 제공한다.

operation::admin-requirement-set-list[]

==== 단과대 목록 조회

단과대 목록을 id·이름과 함께 조회한다. 졸업 요건 세트 필터·등록 드롭다운의 선택지로 사용된다.

operation::admin-college-list[]

==== 학과 목록 조회

학과 목록을 id·단과대(id·이름)·학과명과 함께 조회한다. collegeId를 주면 해당 단과대 소속만, 미지정이면 전체. 사용자는 이름을 보고 고르고 프론트는 id로 요청/응답한다.

operation::admin-department-list[]

==== 졸업 요건 세트 단건 조회

세트 1건과 연결된 졸업 규칙 ID 목록을 조회한다.

operation::admin-requirement-set-detail[]

==== 졸업 요건 세트 생성

새 졸업 요건 세트를 만들고 선택한 졸업 규칙들을 연결한다. 버전은 요청으로 받지 않고 서버가 (학과, 적용년도) 단위로 1부터 자동 채번한다. 활성으로 등록하면 같은 학과에 적용년도가 겹치는 다른 활성 세트가 없어야 하며, 겹치면 409를 반환한다. 생성된 ID를 반환한다.

operation::admin-requirement-set-create[]

==== 졸업 요건 세트 수정

세트의 정보(적용년도·설명·이미지·활성)와 연결 규칙을 전체 교체(PUT)한다. 학과·단과대·버전은 생성 시 확정되어 수정할 수 없으므로 요청에 포함되지 않는다. 적용년도가 바뀌면 버전을 새 (학과, 적용년도) 기준으로 다시 부여하고 그대로면 기존 버전을 유지한다. 활성으로 둘 경우 적용년도가 겹치는 다른 활성 세트가 없어야 한다(겹치면 409).

operation::admin-requirement-set-update[]

=== 학업 정보

==== 성적표 조회

로그인한 회원의 성적표 메타 정보와 수강 이력 전체를 조회한다. 메타에는 단과대학명·학과·총취득학점·평점 평균·성적표 생성/수정 시각이 포함되며, 수강 이력은 학기 오름차순으로 그룹핑하여 반환한다.

operation::transcript-get-report[]

==== 성적표 등록

취득교과목 영역별 분류표 PDF를 업로드하면 자동으로 파싱하여 학업 정보를 저장한다. 기존 성적표가 있으면 소프트 삭제 후 새로 생성한다.

operation::transcript-create[]

==== 수강 이력 수정

변경 후의 전체 수강 이력 목록을 받아 기존 이력을 통째 치환한다(수정·삭제·추가). 치환 후 총취득학점과 평점 평균(GPA)을 재계산하여 전체 수강 이력과 함께 반환한다. 메타 정보는 수정할 수 없다. 성적표가 없으면 404를 반환한다.

operation::transcript-update-course-records[]

=== 학업 리포트

==== 학업 리포트 조회

로그인한 회원의 졸업 요건 판정 결과를 조회한다. 전체 달성률 요약과 courseType별 이수 현황을 반환한다.

operation::graduation-get-report[]

성적표가 없으면 404(GRADUATION404_1), 학생의 학과·입학년도에 적용 가능한 활성 졸업 요건 세트가 없으면 404(GRADUATION404_2)를 반환한다. 적용 가능한 활성 세트가 없을 때의 응답은 다음과 같다.

operation::graduation-get-report-no-requirement-set[]

==== 영역별 이수 현황 조회

courseType 내 areaType별 상세 이수 현황을 조회한다. areaType별 이수 과목 목록(필수/선택), 미충족 사유, 해당 courseType 전체 학점 현황을 반환한다.

operation::graduation-get-area-detail[]

==== 관리자 PDF 리포트 미리보기

ADMIN·SUPER_ADMIN 전용 일회성 PDF 판정. 이름·학번 일치 검사 및 DB 저장 없이 일반 사용자와 같은 파서·판정기·리포트 조립기 사용.
주전공에 적용 가능한 활성 세트가 필요하며, 일반 리포트와 동일한 정확도 경고 정책 적용.
한 요청으로 요약과 모든 영역 상세 반환. 회원 정보·원본 PDF·파싱 원문은 응답 제외, 응답 캐시 금지.

operation::admin-report-preview[]

=== 자주 묻는 질문(FAQ)

==== FAQ 목록 조회

FAQ를 최신순으로 조회한다. 읽기 전용이며 비로그인 상태에서도 호출할 수 있다(화면의 '자주 묻는 질문'이 홈 푸터에 있다). 목록 한 건이 곧 아코디언 한 줄이라 제목과 본문을 함께 반환한다. 본문은 마크다운이 아닌 줄바꿈 포함 평문이다.

operation::faq-list[]

`tag`를 주면 해당 태그만 조회한다(SERVICE=서비스, COMMON=공통, MAJOR=전공). 미지정이면 전체이며, 화면 상단 칩의 '전체'가 여기에 해당한다.

operation::faq-list-by-tag[]

operation::admin-faq-update[]

=== 동글맵 장소

동글맵은 로그인 회원 누구나 조회하고, 장소 등록·정보 수정은 PDF 본인인증 또는 학교 이메일 인증 회원만 할 수 있다. 카테고리는 음식점·카페·술집·스터디·생활·오락·기타 7개이며 상세카테고리는 각 카테고리에 속해야 한다. 숨은 맛집 태그(`tags`: 지름길·공부·회식·밥약·분위기·혼밥·커피·진짜 맛집)는 카테고리와 별개로 0개 이상 붙이며, 정보 수정에서 함께 바꾼다(버전 충돌·수정 이력 포함). 목록·상세 응답의 `tags`는 enum 순서로 중복 없이 내려간다. 미인증 회원의 쓰기 요청은 403(PLACE403_1)을 반환한다. 좌표는 사용자가 지도 중심 핀으로 지정한 값만 저장하고 주소는 저장하지 않는다.

==== 지도 장소 목록 조회

숨기지 않은 장소 전체를 핀 표시용 최소 정보로 반환한다. 서비스 영역이 캠퍼스 반경 1.5km라 화면 영역별 조회 없이 한 번에 내려주며, 카테고리 필터는 클라이언트에서 적용한다.

operation::place-list[]

==== 장소 상세 조회

장소 정보와 입력 순서의 메뉴(메뉴별 추천 여부 포함), 최초 등록 시각·마지막 정보 수정 시각, 정보 수정에 쓸 버전, 최초 등록자 닉네임을 반환한다. 닉네임은 저장하지 않고 조회 때마다 회원 정보에서 가져오며, 등록자가 탈퇴했으면 null이다. 수정자는 공개하지 않는다. 없거나 숨긴 장소는 404(PLACE404_1)를 반환한다.

operation::place-detail[]

==== 등록 전 중복 장소 확인

핀 반경 50m 안 장소의 이름을 공백·특수문자 제거, 영문 소문자로 정규화해 비교한다. 같으면 `exact`(등록 불가), 한쪽이 다른 쪽을 포함하면 `similar`(확인 안내)로 반환한다.

operation::place-duplicates[]

==== 장소 등록

장소를 등록하고 생성된 ID를 반환한다. 이름·위치·카테고리는 등록 후 변경할 수 없다. 서비스 영역 밖은 400(PLACE400_1), 카테고리 짝 불일치는 400(PLACE400_2), 그 밖의 값 오류는 400(PLACE400_3 또는 VALID400_1), 반경 50m 안에 정규화 이름이 같은 장소가 있으면 409(PLACE409_1)를 반환한다.

operation::place-register[]

==== 장소 정보 수정

인증 회원 누구나 영업시간·설명·메뉴를 고친다. 메뉴는 보낸 목록 전체로 교체하고(추천 여부를 생략한 메뉴는 추천 아님, 추천 여부만 바꿔도 수정), 비우거나 null인 영업시간·설명은 삭제한다. 상세 조회로 받은 `version`을 함께 보내며, 그사이 다른 회원이 먼저 수정했으면 409(PLACE409_2)를 반환한다. 수정할 때마다 변경 전후 값을 수정 이력에 남기고, 바뀐 값이 없으면 이력·버전·마지막 정보 수정 시각을 그대로 둔다. 없거나 숨긴 장소는 404(PLACE404_1), 값 오류는 400(PLACE400_3 또는 VALID400_1)을 반환한다.

operation::place-info-edit[]

==== 장소 신고

등록자를 포함한 인증 회원 누구나 장소를 신고한다. 서로 다른 회원의 처리 대기 신고가 3건이 되면 장소를 자동으로 숨기고(신고는 관리자 확인을 위해 대기로 남김), 그 밖의 처리는 관리자가 한다. 접수가 커밋되면 운영 디스코드 채널로 알린다(신고자 정보 제외, 웹훅 주소 미설정 시 생략). 사유가 기타(`OTHER`)면 설명이 필요하다(400, PLACE400_4). 회원당 장소별 처리 대기 신고는 1건이며 대기 신고가 있으면 409(PLACE409_3), 처리된 뒤에는 다시 신고할 수 있다. 없거나 숨긴 장소는 404(PLACE404_1)를 반환한다.

operation::place-report[]

==== 장소 리뷰 목록

로그인 회원 본인의 포인트를 조회한다. 포인트는 활동 이벤트를 받아 서버가 자동으로 적립하며 적립 API는 없다.

[cols="2,1,4"]
|===
|사유 |적립액 |기준

|`GRADUATION_REPORT_FIRST_VIEW` |500 |졸업 리포트 요약을 처음 조회했을 때. 회원당 1회
|`PLACE_REGISTER` |500 |장소를 등록했을 때. 장소가 숨겨지면 회수, 해제되면 복구

|`PLACE_REVIEW` |100 |그 밖의 리뷰. 첫 리뷰와 합쳐 회원당 장소별 1회(지웠다 다시 써도 다시 받지 않음). 리뷰가 숨겨지면 회수
|`PLACE_INFO_EDIT` |100 |장소 정보를 실제로 바꿨을 때. 회원당 장소별 1회
|`MYSTERY_SOLVED` |10 |정각원의 비밀 정답 해결. 회원·한국시간 문제 날짜별 1회
|===

본인이 리뷰를 지워도 회수하지 않는다. 회원이 탈퇴하면 포인트 내역을 지운다. 장소 등록·리뷰 작성·정보 수정 적립은 그 요청이 커밋된 직후 응답 전에 반영되며, 적립이 실패해도 원래 요청은 성공으로 응답한다. 추리 정답 해결과 10P 적립은 같은 트랜잭션으로 저장되며 적립 실패 시 정답 처리도 롤백된다. 숨김에 따른 회수·복구는 비동기로 반영된다.

== 동아리 쇼핑

로그인 회원 누구나 조회하고, 등록·수정·모집 요청은 PDF 본인인증 또는 학교 이메일 인증 회원만 할 수 있다(미인증 403, CLUB403_1). 일시는 한국 시간이며, 모집 상태(`BEFORE`·`OPEN`·`CLOSED`)는 조회 시각 기준으로 서버가 계산한다. 기간 모집은 시작 포함·마감 제외로 열리고, 조기 마감은 기간보다 우선하며, 상시모집은 기간 없이 열려 있다.

=== 동아리 목록 조회

필터 종류끼리는 모두 만족해야 하고, 같은 필터 안에서는 하나라도 해당하면 통과한다. 정렬에서 같은 값끼리는 이름(가나다)순이다. 12개씩 내려주며 다음 묶음은 `nextCursor`를 `cursor`로 넘겨 받는다. 커서는 마지막 동아리의 정렬 위치라 그사이 동아리가 추가·삭제돼도 중복 없이 이어지고, 형식이 맞지 않으면 400(CLUB400_1)을 반환한다. 사진·찜·배너는 후속 API에서 채운다.

=== 관리자 동아리 관리

`/api/admin/clubs/**`는 관리자만 호출한다. 요청자와 직접 수정 권한 회원은 실명과 회원 ID로 보여준다. 승인하면 요청 값을 바로 반영하고(신규 등록은 정식 동아리 생성, 임시 등록 동아리는 정식 전환), 요청자에게 그 동아리의 직접 수정 권한을 준다. 같은 요청을 두 관리자가 동시에 처리하지 않도록 잠그며, 이미 처리된 요청은 409(CLUB409_4), 반려 사유가 비거나 200자를 넘으면 400(CLUB400_6)이다.

승인 적립은 승인과 같은 트랜잭션에서 저장하고, 적립에 실패하면 승인도 롤백된다. 최초 등록 500P(`CLUB_FIRST_REGISTRATION`)는 동아리당 1회(신규 등록 승인 또는 임시 등록 동아리의 첫 승인), 모집 100P(`CLUB_RECRUITMENT`)는 이 동아리가 처음 모집하는 기수의 새 모집 건, 기수 갱신 100P(`CLUB_GENERATION_UPDATE`)는 정보 수정으로 현재 기수가 올라갈 때이며 둘 다 동아리·기수당 1회다. 대상 ID는 최초 등록이면 동아리 ID, 모집·기수 갱신이면 동아리 ID × 10000 + 기수다. 관리자 직접 수정·임시 등록과 권한 회원의 바로 반영은 적립하지 않는다. 탈퇴한 요청자의 요청은 반영만 하고 권한·적립은 없다.
